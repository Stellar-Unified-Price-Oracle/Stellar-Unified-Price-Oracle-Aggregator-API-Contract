# Migrating to v0.2.0

- **Interface version:** 0.2.0 (previous: 0.1.0)
- **Contract WASM hash:** see `interface/versions.json`
- **Deprecation window:** none — the 0.1.0 artifact was stale, and these
  changes were already live in the contract when 0.2.0 was published.

The 0.1.0 artifact was not regenerated while the contract grew from 274 to 640
endpoints. 0.2.0 catches the published interface up with the contract. Of the
274 original functions, 8 changed; the other 366 functions are additions.

## Summary of breaking changes

| Change | Kind | Replacement |
|---|---|---|
| `challenge_price(asset, expected_price, proof_data)` | signature | `challenge_price(challenger, asset, expected_price, proof_data)` |
| `claim_rewards()` | signature | `claim_rewards(claimer)` |
| `dispute_proposal(proposal_id)` | signature | `dispute_proposal(disputer, proposal_id)` |
| `propose_price(asset, price, timestamp, bond_amount)` | signature | `propose_price(proposer, asset, price, timestamp, bond_amount)` |
| `set_cross_chain_deviation_threshold(threshold_bps)` | removed | `set_cc_deviation_threshold(threshold_bps)` |
| `get_cross_chain_deviation_threshold()` | removed | `get_cc_deviation_threshold()` |
| `set_cross_chain_verification_enabled(enabled)` | removed | `set_cross_verify_enabled(enabled)` |
| `is_cross_chain_verification_enabled()` | removed | `is_cross_verify_enabled()` |

The four signature changes add the acting address as the first argument. That
address must authorize the call, so a challenge, claim, dispute or proposal is
always attributable to the account that made it.

## Before / after

### Before (0.1.0)
```js
await oracle.challenge_price({ asset, expected_price, proof_data });
await oracle.claim_rewards();
await oracle.set_cross_chain_verification_enabled({ enabled: true });
```

### After (0.2.0)
```js
await oracle.challenge_price({ challenger: me, asset, expected_price, proof_data });
await oracle.claim_rewards({ claimer: me });
await oracle.set_cross_verify_enabled({ enabled: true });
```

## Behavioural changes (no signature change)

- **Source removal recomputes at most 2 assets inline.** Removing a source
  re-derives the aggregate of the assets it fed. Each re-derivation writes about
  ten ledger entries and a transaction may touch at most 100, so only the first
  2 run inside the removal; the rest are listed in `RecomputeDeferredEvent`.
  Call the permissionless `recompute_asset_price` for each listed asset.
- **Circuit-breaker re-arm needs recorded source recovery.** Automatic re-arm
  (`evaluate_breaker_rearm`) now also needs `record_breaker_source_recovery`
  (admin) after the trip. Once open past its escalation bound, the breaker no
  longer panics with `BreakerEscalationRequired`: the call returns `false` and
  emits `BreakerEscalatedEvent`. Re-arming lifts the pause the trip applied.
- **Upgrades from earlier builds must call `enable_all_feature_flags` once.**
  Optional settings are now only read when a flag says they were configured.
  Settings written before the upgrade have no flag, so without this call they
  would be ignored.
- **History shard buckets span 256 ledgers** (previously one week, which
  overflowed Soroban's 64 KiB entry cap after about 500 updates). Persistent-tier
  history written into weekly buckets is not read back by this version. No
  deployment is recorded in `interface/versions.json`, so no such data is
  known to exist; a deployment that has some must re-export it before
  upgrading.

## Checklist for consumers
- [ ] Bump `@stellar-unified-price-oracle/interface` to `0.2.0`
- [ ] Pass the acting address to `challenge_price`, `claim_rewards`,
      `dispute_proposal` and `propose_price`
- [ ] Switch to the renamed cross-chain verification functions
- [ ] Operators upgrading a deployed contract: call `enable_all_feature_flags`
- [ ] Run `python3 scripts/devx/lint_deprecated.py <your-src>`
